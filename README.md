# fastapi_grpc_demo

```python3 -m pip install fastapi\[all\]```  

Установка зависимостей, официальные библиотеки для работы с gRPC и генерации кода из .proto файлов:  
```python3 -m pip install grpcio grpcio-tools```  

```
fastapi_grpc_demo/
├── message.proto      # Описание контракта (данных и методов)
├── grpc_server.py     # gRPC-сервер (получатель)
└── main.py            # FastAPI-приложение (отправитель / клиент)
```

Генерируем Python-код из .proto:  
```python3 -m grpc_tools.protoc -I. --python_out=. --grpc_python_out=. message.proto```  
После этого в папке автоматически появятся два новых файла: message_pb2.py (классы сообщений) и message_pb2_grpc.py (классы клиента и сервера). Редактировать их вручную не нужно.  


Запуск и проверка, понадобятся два окна терминала:  
```python3 grpc_server.py```  
```uvicorn main:app --reload```  

Открой в браузере http://127.0.0.1:8000/, протестируй эндпоинт /hello/{name} (например, передай имя Алиса) и посмотри на логи в обоих терминалах.  


• service Greeter — это список функций, которые умеет выполнять сервер. У нас она одна: SayHello.  
• message HelloRequest — структура входящих данных. Цифра = 1 — это не значение, а порядковый номер поля. По сети передаётся не слово "name", а просто цифра 1, что делает gRPC очень быстрым.  


• message_pb2.py — содержит классы HelloRequest и HelloReply (умеют превращать данные в байты и обратно).  
• message_pb2_grpc.py — содержит заготовки для сервера и клиента.  


### Разбор по файлам

#### Файл message.proto — «Договор»

В обычном REST API клиент и сервер могут не знать заранее, какие поля придут в JSON. В gRPC всё строго:  
• service Greeter — это список функций, которые умеет выполнять сервер. У нас она одна: SayHello.  
• message HelloRequest — структура входящих данных. Цифра = 1 — это не значение, а порядковый номер поля. По сети передаётся не слово "name", а просто цифра 1, что делает gRPC очень быстрым.  

#### Команда protoc — «Генератор»

Python не умеет читать .proto файлы напрямую. Команда grpc_tools.protoc берёт твой договор и автоматически пишет за тебя сложный сетевой код в двух файлах:  
• message_pb2.py — содержит классы HelloRequest и HelloReply (умеют превращать данные в байты и обратно).  
• message_pb2_grpc.py — содержит заготовки для сервера и клиента.  

#### Файл grpc_server.py — «Исполнитель»

Этот файл ждёт звонков по gRPC и отвечает на них.  
• class GreeterService(message_pb2_grpc.GreeterServicer) — мы берём сгенерированную заготовку сервера и дописываем в неё реальную логику.  
• async def SayHello(self, request, context) — функция сработает, когда придёт запрос. В request.name уже лежит распакованное имя, а в context хранится техническая информация (например, IP клиента или тайм-ауты).  
• server.add_insecure_port("[::]:50051") — сервер открывает порт 50051 без шифрования (SSL/TLS), что идеально для локальной разработки.

#### Файл main.py — «Посредник»

Здесь работает FastAPI, который притворяется обычным веб-сайтом, но под капотом дёргает gRPC.  
• lifespan(app: FastAPI) — это менеджер жизненного цикла приложения. Открывать сетевое соединение с gRPC на каждый запрос слишком долго. Поэтому мы открываем «трубу» (channel) один раз при запуске FastAPI и закрываем её только при выключении.  
• stub = message_pb2_grpc.GreeterStub(channel) — слово stub переводится как «заглушка». Это специальный объект-помощник: ты вызываешь у него метод так, будто это обычная локальная функция, а он сам отправляет данные по сети на другой сервер.  
• response = await stub.SayHello(request) — самая главная строчка. В этот момент FastAPI ставит обработку на паузу (await), отправляет данные на порт 50051 и ждёт, пока grpc_server.py вернёт ответ.
